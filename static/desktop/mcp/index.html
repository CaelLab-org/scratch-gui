把你本机的 AI 客户端接进编辑器

桌面版打开项目后，支持 MCP 的 agent（Claude Code、ZCode、Codex 等）可以用编辑器同一套 工具读写它：读积木、改脚本、加角色、跑起来截图。通道只监听本机。

最省事的一条路：复制设置里的那段话

编辑器里 设置 → 外部接入，开启后会给你一段写好的话：地址、密钥、 先看工具有哪些、怎么调用、几条别踩的坑，全在里面。整段复制，粘进 Claude Code、 ZCode、Cursor 或任何能跑命令的对话框，它就知道怎么接 —— 能加 MCP 就用 MCP， 不能就照里面的命令敲。

那段话有简中 / 繁中 / 英 / 日四版，默认跟着编辑器语言，面板里也能手动切。

前提

  • 装了 Windows 桌面版，并打开了一个项目。网页版没有这条通道。
  • 本机有 Node.js 20 或更新版本（客户端要能跑 npx）。

一条命令接上 Claude Code

claude mcp add xce -- npx -y xce-mcp

其余客户端用同一条命令参数：command 是 npx， args 是 ["-y", "xce-mcp"]。

各客户端的配置位置

ZCode

设置 → MCP → 添加，选 stdio，命令填 npx -y xce-mcp。或者写进 ~/.zcode/cli/config.json：

{
  "mcp": {
    "servers": {
      "xce": {
        "command": "npx",
        "args": ["-y", "xce-mcp"]
      }
    }
  }
}

Cursor

写进 ~/.cursor/mcp.json（全局）或项目里的 .cursor/mcp.json：

{
  "mcpServers": {
    "xce": {
      "command": "npx",
      "args": ["-y", "xce-mcp"]
    }
  }
}

VS Code

写进项目里的 .vscode/mcp.json，注意这层键叫 servers：

{
  "servers": {
    "xce": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "xce-mcp"]
    }
  }
}

Codex CLI

写进 ~/.codex/config.toml：

[mcp_servers.xce]
command = "npx"
args = ["-y", "xce-mcp"]

Cline / Windsurf 等

都认通用的 mcpServers 结构（同上面的 Cursor 那段）。 Cline 在 Settings → MCP Servers 里加；Windsurf 写在 ~/.codeium/windsurf/mcp_config.json。

接上之后能做什么

  • 读项目：角色清单、舞台、脚本、造型、声音；脚本读回来带积木 id，方便改。
  • 写项目：新建 / 替换 / 删除脚本，加角色、改造型、加删声音、改名，改完能通过编辑器自己的撤销回退。
  • 跑起来：触发绿旗或广播，等一会儿截图看结果。
  • 项目记忆：读写这个项目级的长期笔记，跟面板里的 XCE Agent 共用一份。
  • 联网：读公开网页（桌面版走应用自己发请求，不受浏览器跨域限制）、搜 CaelLab Search。

边界：一次调用结束后才轮得到下一次；面板自己正在跑一轮时，外部来的写操作会被拒绝， 等它结束再试。读操作不受影响。

截图（xce_read_stage / xce_read_costume）不走 base64：桌面端会把图落成 一个短时效地址（MCP 通道是 http://127.0.0.1:端口/xce/shots/…；走 HTTP 外部接入时用 你连过来的地址，内网就是局域网 IP），地址直接写在工具结果里，10 分钟内可以反复取。地址里的 随机串本身就是凭据，取图不用带密钥。

技能（skill）

编辑器里那套参考文档（内置 6 份 xce_fastdocs_*，加上你自己写的）会以 MCP prompt 的形式出现在客户端里 —— 客户端列出 prompt 时就能看到名字和一行描述， 选中哪份就实时从编辑器读正文，不在这个包里存副本。

也就是说：在编辑器「设置 → 技能」里新增，或者从 .md 文件导入一份， 面板里的 XCE Agent 和接进来的外部客户端都能用同一份，不用两边各写一遍。

SKILL.md 格式

---
name: my_rules
description: 一行话，写清什么时候该读它
---

正文，随便写。模型先看到上面两行，需要时才读这里。

名字只能是字母、数字、下划线、连字符（2~40 位）；没有 --- 头也能导入， 那就按文件名起名。最多 20 份，单份正文 8000 字以内。

另一台机器 / 网页里的 AI：走网络

本机桥只监听 127.0.0.1，别的机器连不上。要让同一局域网里的机器、 或者只能发 HTTP 请求的 AI 用上，在编辑器的 AI 面板里打开「设置 → 外部接入」： 它会生成一串 API 密钥，并在 49621 端口开一个 HTTP 入口。关掉开关立刻停。

入口有个「监听范围」开关，默认是对局域网开（0.0.0.0）；只给本机用就切成 「仅本机」，它只绑 127.0.0.1，别的机器再怎么试也连不上。换范围会立刻重开监听。

入口只有五个路由，没有文件系统、没有 shell：

curl -s http://127.0.0.1:49621/v1/health
curl -s http://127.0.0.1:49621/v1/instructions -H "Authorization: Bearer xce_..."
curl -s http://127.0.0.1:49621/v1/tools -H "Authorization: Bearer xce_..."
curl -s http://127.0.0.1:49621/v1/call -H "Authorization: Bearer xce_..." \
  -H "Content-Type: application/json" -d '{"name":"xce_read_project","args":{}}'

# 音频这类大文件：先传原始字节，再拿 assetId 调 xce_add_sound
curl -s -X POST "http://127.0.0.1:49621/v1/assets?name=blast.mp3&mime=audio/mpeg" \
  -H "Authorization: Bearer xce_..." --data-binary @blast.mp3

/v1/instructions 是编辑器自己的系统提示词（项目规矩、工具用法、 积木文本格式、用户自定义提示词和记忆索引）。它跟 MCP 客户端启动时收到的 instructions 是同一份；客户端没转给模型的话，调 xce_read_instructions 也能读到。素材上传有 30 分钟有效期， 只存在内存里，传完就用掉。

命令行工具 xce-cli 两种通道都认：不传 --url 走本机桥 （不需要密钥），传了就换成网络入口。 

npx -y @caellab/xce-cli@latest instructions
npx -y @caellab/xce-cli@latest tools
npx -y @caellab/xce-cli@latest call xce_read_project '{}'
npx -y @caellab/xce-cli@latest mcp --url http://192.168.1.10:49621/v1 --key xce_...
npx -y @caellab/xce-cli@latest skill --out SKILL.md

最后一条会写一份 SKILL.md，丢给那些「只会跑命令、不接 MCP」的 agent。 密钥别写进项目文件，也不用的时候把开关关掉。

它怎么找到编辑器

桌面版启动时在主进程开一个只监听 127.0.0.1 的桥，端口随机； 端口和一次性口令写进 %APPDATA%\XMUER Coding Engine\ai-bridge.json， xce-mcp 读这个文件去连。应用退出时文件删除，下次启动口令重新生成。

调试时可以用环境变量跳过发现文件：

变量作用
XCE_BRIDGE_FILE换一个发现文件
XCE_BRIDGE_PORT / XCE_BRIDGE_TOKEN直接给端口和口令

排错

现象怎么处理
客户端里根本没有 xce 这组工具 先在终端跑 npx -y xce-mcp，看是装包失败还是启动报错；再确认客户端配置的键名（mcpServers / servers / mcp.servers）没写错。
调用报 editor is not connected 桌面版开着但没打开项目。在应用里打开任意项目，再试。
应用压根没开 工具清单还能列出来（读的是上次缓存），但调用会失败。先把应用开起来。
写操作被拒绝 面板里的 XCE Agent 正在跑一轮。等它结束；或者先把面板那一轮停掉。
E_AUTH 口令对不上，通常是应用重启过。重新启动客户端，让它重读发现文件。
prompt 加载不出来 prompt 的正文是从编辑器实时读的，应用没开或没打开项目时只有清单、没有正文。

安全

  • 桥只监听 127.0.0.1，外网连不进来；端口随机、口令每次启动重新生成。
  • 接进来的客户端能读也能改你当前打开的项目 —— 只接你信得过的客户端。
  • xce-mcp 只做传输，不含编辑器代码，按 Apache-2.0 发布；编辑器本身是 AGPL-3.0-only。
