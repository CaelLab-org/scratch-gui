## A. 改上一轮发言 + 分叉

**数据**：用户条目加稳定 `id`（`u-<ts>-<rand>`），同一个 id 也写进 `session.messages` 的 user 消息（`session.js` 的 `toModelMessages` 本来就会剥掉 `id`，模型看不到）。

**编辑（只最后一条）**：最后一条用户气泡 hover 露出铅笔 → 原地变成 textarea（保存 / 取消）→ 保存后按这条的 `id` 把 `items` 和 `session.messages` 一起截断，再用新文本**自动重发**（ZCode 就是自动重发，不是回填输入框）。做法：把 `handleSend` 里「拿 draft 之后」的部分抽成 `sendText(text)`，编辑重发复用它。

**分叉（每一轮末尾）**：轮尾 hover 露出「分叉」→ 以「这一轮结束」为切点，把 messages / items 各截一份写进**新会话**（原来那条完整留在库里，什么都不删），记 `forkOf: {id, title}` 后切过去并提示。`store.js` 加 `saveFork(id, session, items, parent)`，历史列表上给分叉来的会话标一行「分叉自 xxx」。

**边界**：正在跑的时候先中止当前轮再执行（跟 ZCode 一致）；只允许对「已完成、且是轮尾」的轮分叉。

**测试**：`turns.test.mjs` / `store.test.mjs` 补断言（截断切点正确、fork 不污染原会话、parent 字段落盘）。

## B. AI 记忆 + 技能

**存储**：localStorage（`xce_ai_memories` / `xce_ai_skills`），网页版和桌面版走同一套 —— 记忆不是密钥，没必要进桌面版的 settings.json。记忆是**浏览器级全局**的，不按对话分。

**记忆形状**：`{id, name, description, type, body, createdAt, updatedAt}`，`type` 沿用 ZCode 的四类（user / feedback / project / reference，界面上标「用户偏好 / 工作方式 / 项目 / 参考」）。上限：60 条、单条正文 4KB、注入提示词的索引截到 8KB 并提示已截断。

**工具 3 个**（英文描述，按你的「AI 一律用英文」规矩）：
- `xce_save_memory {name, description, type, body}` —— 按 name 覆盖或新建（ZCode 是「先查再更新，不要建重复的」）
- `xce_delete_memory {name}`
- `xce_read_memory {name}` —— 读正文全文

**提示词**：只注入 `name — description` 的索引（照 ZCode 的两段式），正文按需读，绝不整篇塞进去。另加一节说明何时该记、何时该删该改；详细做法写进新的 `docs/skills/xce_memory/SKILL.md`（这就是你说的「有 skill」）。

**技能**：内置那 4 份保持只读；用户技能存 localStorage，合并进 `createTools({skills})` 的清单（`xce_read_skill` / `xce_read_fast_docs` 自动就能读到）。保存时校验名字不与内置重名。

**设置页**：新增「记忆」页（列表 + 类型标签 + 新增/编辑/删除，改动立即落盘）和「技能」页（内置只读 + 「我的技能」增删改）。

## C. 配置导出 / 导入合并

**文件名**：`xce-ai-config-YYYYMMDD.output.xce`（JSON 文本，用你建议的 `.output.xce` 后缀）。

**内容**：`{format:'xce-ai-config', version:1, app, exportedAt, settings, keys, customProviders, models, userPrompt, memories, skills}`。**默认含 API 密钥**（否则迁不了机器），导出按钮旁给一个「包含密钥」勾选框，取消勾选就不带；界面上直接警示「这个文件等于你的密钥，别外传」。**不含对话记录**（体量大且不是配置）。

**导出**：Blob + `<a download>`；**导入**：隐藏 `<input type="file">` + FileReader，导入前校验 `format`/`version`，不认识就拒绝而不是乱写。

**合并策略**（照 ZCode）：文件里的值**覆盖**同名项，本地独有的项**保留不动**，导完给一份摘要「合并了什么 / 跳过了什么 / 哪儿不对」，而不是一句「导入成功」。

**设置页**：新增「备份与迁移」分区（导出 / 导入 / 清除密钥）。

## D. xce_note（Scratch 原生注释）

**先说清一个技术事实**：Scratch 的原生注释**必须挂在某块积木上** —— VM 的 `blocks.toXML(comments)` 只输出挂在积木上的注释，没有锚点的注释在编辑器里根本不显示。所以签名是 `xce_note {sprite, text, blockId?}`，`blockId` 省略时挂到该角色**最新那段脚本的顶块**上；这个角色一块积木都没有时明确报错（说明 Scratch 本身做不到），让 AI 转告用户。

**实现**：`port.js` 加 `createNote`，走 `target.createComment(id, blockId, text, x, y, 200, 120, false)` + `emitWorkspaceUpdate()`（已确认 GUI 的 `clearWorkspaceAndLoadFromXml` → `domToWorkspace` 支持注释节点）。**同一个顶块已经有注释就改文本**，不再叠一张，免得刷出一堆注释。

**声明**：前缀由 port 强制加（模型不用自己写、也不许重复写）。

**撤销**：返回 `{kind:'note', sprite, commentId}` 句柄 → 单卡「撤销」和「回退本轮变更」都能删掉它；`turns.js` 的 `summarizeChanges` 加 `notes` 计数（变更行显示「+1 注释」）。注释创建本身会触发 `emitProjectChanged`，项目快照会跟着存。

**视图**：不擅自把用户正在看的角色切走 —— 注释写在非当前角色上时，AI 在回复里告诉用户「切到那个角色就能看到」。

**提示词**：工具表加一行，并说明注释是写给用户看的、别写只有自己懂的东西。
